# Shared-Phase Temporal Gradients for Low-Step ANN-to-SNN Adaptation

**English** | [简体中文](README.zh-CN.md)

This project implements ANN-to-SNN conversion and adaptation with ResNet18 and ResNet50. The method constructs temporal surrogate gradients from responses under a shared initial phase, while retaining hard spiking forward propagation during training. Inference executes one SNN trajectory and one final classifier.

A teacher ANN is used only by training configurations with knowledge distillation. Inference requires no teacher, multiple views, or repeated full-model prediction fusion. The optional M3 integer-event extension increases event precision and capacity, so its results should not be interpreted as equal-cost comparisons with binary spikes.

## Installation

Python 3.10+ and PyTorch 2.2+ are required:

```bash
pip install -r requirements.txt
```

Commands default to CPU. Select a logical GPU with `--device cuda:0` and physical GPUs through `CUDA_VISIBLE_DEVICES`. The examples below use physical GPUs 2 and 3; with `CUDA_VISIBLE_DEVICES=2,3`, they become logical GPUs 0 and 1.

The original SNN adaptation experiments used two-GPU `DataParallel`, with local BatchNorm statistics on each GPU and running buffers retained from the primary GPU. Enable this layout with `--data-parallel`.

## Data and weights

### Dataset preparation

Use the extracted Python versions of CIFAR-10 and CIFAR-100. `--data` accepts either the dataset directory or its parent, for example:

```text
data/
  cifar-10-batches-py/
  cifar-100-python/
  CIFAR-100-C/            # Optional corruption benchmark
```

The commands do not download data automatically. Training reads only training data; the official test set is accessed by a separate evaluation command.

CIFAR-100 uses the supplied [fixed partition](configs/cifar100_split.json):

| Role | Images | Source |
|---|---:|---|
| Training `training` | 42,000 | Official training set |
| Calibration `calibration` | 1,000 | Official training set |
| Development evaluation `selection` | 2,000 | Official training set |
| Confirmation evaluation `confirmation` | 5,000 | Official training set |
| Official test | 10,000 | Official test set |

**The confirmation partition comes from the training set and is separate from the official test set.** The four training-set partitions are disjoint.

CIFAR-10 uses all 50,000 training images, with no additional internal validation partition. The public source ANN was selected using the official test set; subsequent conversion experiments inherit that test-set exposure.

For CIFAR100-C, provide a directory containing `labels.npy` and the corruption arrays. Evaluation covers the 15 corruption types used in the paper, each at five severities, for 75 cases in total.

### Checkpoint preparation

[weights.json](configs/weights.json) lists recommended filenames and SHA256 checksums for the original checkpoints. A pinned download URL is available for the upstream CIFAR-10 ANN.

**Project-trained checkpoints have not yet been hosted publicly.** The commands below assume that the corresponding weights have been placed in a local `weights/` directory. The weight catalog does not contain model files.

Both original experiment checkpoints and checkpoints generated by this public runner support inference. A final SNN checkpoint contains all required weights and thresholds, so evaluation needs no source ANN, teacher, calibration cache or previous experiment directory. Select the matching preset: state tensors alone do not encode every timestep and event-capacity setting.

## Quick evaluation

For CIFAR-100, ResNet18, M3/T2:

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/evaluate.py c100-m3-t2 \
  --checkpoint weights/c100-m3-t2.pt --data data \
  --device cuda:0 --batch-size 1024 --output runs/c100-m3-t2-test.json
```

Change the preset and checkpoint to evaluate `c100-m3-t4`, `c10-m3-t2`, or another configuration.

- The default is official test-set evaluation.
- `--split selection` or `--split confirmation` evaluates the corresponding CIFAR-100 training-set holdout.
- `--unadapted` accepts a QAT checkpoint, converts it to the selected SNN, and evaluates it without SNN adaptation training.

CIFAR100-C evaluation:

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/evaluate.py c100-phase-t2 \
  --checkpoint weights/c100-phase-t2.pt --corruptions data/CIFAR-100-C \
  --device cuda:0 --output runs/phase-corruptions.json
```

## Training and reproduction

### Training settings

[experiments.json](configs/experiments.json) defines the presets:

| Stage | Epochs | Main settings |
|---|---:|---|
| CIFAR-100 ResNet18 source ANN training | 400 | Ordinary ReLU ANN, mixed-label CE |
| QCFS quantization-aware training (QAT) | 200 | Trainable channel thresholds |
| Hard-SNN adaptation | 160 | Fixed thresholds, trainable network parameters |

The recipes use the fixed seed `2026100321`, SGD, five-epoch linear warmup and subsequent cosine learning-rate decay. Augmentation uses pixel-space zero padding, random cropping and horizontal flipping, followed by an equal-probability choice of Mixup or CutMix.

SNN presets with KD use mixed-label CE plus `0.5 × KL(teacher || student)` at temperature 1. The teacher stays frozen and in evaluation mode.

### Main method

Start from a prepared QAT source and an ordinary ANN teacher:

```bash
CUDA_VISIBLE_DEVICES=2,3 python scripts/train.py c100-m3-t2 \
  --data data --source weights/c100-qat.pt --teacher weights/c100-ann.pt \
  --output runs/c100-m3-t2 --device cuda:0 --data-parallel
```

`--source` provides the student's QAT initialization, while `--teacher` provides the ordinary ANN used for distillation. Final evaluation requires only the resulting SNN checkpoint.

### Source preparation

ANN training and QAT use separate presets. To train a CIFAR-100 ResNet18 ANN:

```bash
CUDA_VISIBLE_DEVICES=2 python scripts/train.py c100-ann \
  --data data --output runs/c100-ann --device cuda:0
```

To reproduce the reported QAT route, use the original ANN checkpoint and its matching initial thresholds:

```bash
CUDA_VISIBLE_DEVICES=2,3 python scripts/train.py c100-qat \
  --data data --source weights/c100-ann.pt \
  --thresholds weights/c100-qat-thresholds.pt \
  --output runs/c100-qat --device cuda:0 --data-parallel
```

The CIFAR-100 ResNet18 QAT preset requires initial thresholds whose file records the source ANN's SHA256. An independently retrained ANN requires matching calibration and must not reuse a threshold file with a different recorded source hash.

Other routes:

- **CIFAR-10:** start from the pinned public `c10-ann.pt`, prepare the source with `c10-qat`, then train `c10-phase-t4` or `c10-m3-t2`. When `--thresholds` is omitted, `c10-qat` performs the original recipe's sampled CPU calibration.
- **ResNet50:** use the existing ANN source, followed by `c100-resnet50-qat` and `c100-resnet50-t2`. QAT accepts matching thresholds or performs sampled calibration. This project does not provide a new from-scratch ResNet50 ANN training recipe.

### Memory adjustments and resuming

Use `--batch-size` to fit available memory while retaining the declared training images and total epochs. Actual batch size, parallel layout, optimizer updates and elapsed time are recorded in the output directory.

A new run requires an empty output directory. For runs generated by this public runner, add `--resume` to the original command to restore the optimizer and random streams from `latest.pt`. `--source` and `--thresholds` may be omitted on resume, but KD configurations still require the same teacher checkpoint.

Historical internal-run checkpoints support evaluation; the public runner does not directly resume their optimizer states. Run official test evaluation separately after training, without using official test results to select training checkpoints.

## Configurations and results

`M` is the maximum absolute signed event count per step, and `T` is the number of inference timesteps. R18 and R50 denote ResNet18 and ResNet50.

The following official test-set Top-1 accuracies come from the original completed experiments. The refactored public runner has passed consistency checks but has not undergone a new full-training rerun.

| Preset | Dataset / backbone | M / T | Gradient / objective | Top-1 (%) |
|---|---|---|---|---:|
| `c100-m3-t2` | CIFAR-100 / R18 | 3 / 2 | Shared phase / CE+KD | **80.32** |
| `c100-m3-t4` | CIFAR-100 / R18 | 3 / 4 | Shared phase / CE+KD | 80.46 |
| `c100-phase-t2` | CIFAR-100 / R18 | 1 / 2 | Shared phase / CE | 77.29 |
| `c100-triangular-t2` | CIFAR-100 / R18 | 1 / 2 | Triangular surrogate / CE | 76.46 |
| `c100-diagonal-t2` | CIFAR-100 / R18 | 1 / 2 | Diagonal phase ablation / CE | 73.49 |
| `c100-phase-kd-t2` | CIFAR-100 / R18 | 1 / 2 | Shared phase / CE+KD | 77.87 |
| `c100-phase-kd-t4` | CIFAR-100 / R18 | 1 / 4 | Shared phase / CE+KD | 80.18 |
| `c100-triangular-kd-t4` | CIFAR-100 / R18 | 1 / 4 | Triangular surrogate / CE+KD | 79.34 |
| `c100-resnet50-t2` | CIFAR-100 / R50 | 1 / 2 | Shared phase / CE | 77.97 |
| `c10-phase-t4` | CIFAR-10 / R18 | 1 / 4 | Shared phase / CE+KD | 95.95 |
| `c10-m3-t2` | CIFAR-10 / R18 | 3 / 2 | Shared phase / CE+KD | **96.15** |

The M3/T2 versus M1/T4 comparison changes both timestep count and event capacity. The ResNet50 result evaluates transfer of the complete recipe and does not isolate the effect of the gradient method.

## Costs, figures and tests

Measure inference costs:

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/benchmark.py c100-m3-t2 \
  --checkpoint weights/c100-m3-t2.pt --data data --device cuda:0 \
  --output runs/c100-m3-t2-cost.json
```

Defaults are 1,000 training/calibration images, batch 256, three warmup passes and five timed passes. Inputs are preloaded; preprocessing and event-count hooks are excluded from inference timing. Reports include nonzero signed events, absolute unit counts and magnitude-bit event counts.

The measurement is **dense FP32 PyTorch simulation**, not measured neuromorphic hardware energy or sparse-kernel acceleration. CPU timing is available for functional checks and should not be compared directly with the paper's GPU timing.

Generate mechanism and corruption-comparison figures:

```bash
python scripts/plot.py phase --output figures
python scripts/plot.py corruption --phase runs/phase-corruptions.json \
  --baseline runs/triangular-corruptions.json --output figures/corruptions.pdf
```

Both corruption JSON reports are generated by `evaluate.py --corruptions`, using the corresponding method and baseline checkpoints.

Run CPU unit tests:

```bash
CUDA_VISIBLE_DEVICES='' python -m unittest discover -s tests
```

Tests cover spiking operators, gradient behavior, standalone checkpoint loading and interrupted-run continuation. Use `--help` on each command for the complete argument list, for example:

```bash
python scripts/train.py --help
python scripts/evaluate.py --help
```
